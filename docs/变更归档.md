**规则/决策**:

- **架构定为「一核三端」**:`garden-core`(无 IO 纯函数 + `content/*.json`)三端共用;三种模式 = 三种权威(`LOCAL`/`HOST`/`SERVER`)+ 三个 `GardenPort` 实现。**模式层是边界层,不是新玩法机制**,核心玩法与数值一行不改。
- **世界 World 泛化家庭**:`garden_world`(第 11 张表)供 `world_id`(ULID)+ 世界级 `settings`;各表 `family_id` 列**列名与类型不变**、语义扩为「世界作用域 id」(ihomy 模式下恒等映射),因此**十张既有表的索引与条件 UPDATE 口径一字未动**。
- **互通口径 = 世界与存档可移动 + 按来源分级信任**:`S→C 新世界`可认领(时间戳必须净化 ≤ `imported_at`)、`S→C 已有世界`**禁止回灌**、`P→C` 只经 op-log 重放结算;**积分只在 `platform=IHOMY` 产出**(P2P 结算网关列候选,未排期)。
- **P2P 选房主权威 + op 串行**,不选天真 lockstep、不引 CRDT:判定 guard 与服务器/单人**同一份代码**;离线成员**只交意图不交状态**;房主接管靠 `host_epoch` 单调递增防双主。
- **ihomy 互联 = 同一条 `/api/garden` 协议 + `/garden/meta` 能力协商**:provider 差别只在 `GardenPlatform` 适配层,`IHOMY` 与 `STANDALONE` 的表结构完全相同。
- **新增验收面**:三端 golden 重放一致性(同一 op-log 重放后状态哈希相等)——与「美术看图清单」并列,属接口之外的验收(§22/§23)。
- **未定项**(已写入文档,实现前必须定):世界级删除口径(§29.4)、V2 的 feature code 与 V1 `plant_*` 的替代关系(§30.4)、桌面壳技术栈(§21/§26.6)。

- **「包内目录与 `resources/` 同构」定为硬规则**:代价是 `bundles/audio/audio/**` 的目录重复,收益是**同一路径字符串在 `resources` 与任意 Bundle 间可直接平移**,资源因体积在包间搬迁时玩法代码零改动。

- **命名两条轨道**:资产全小写 snake_case + 11 个类前缀(`ui_`/`ico_`/`bg_`/`crop_`/`plot_`/`fx_`/`pf_`/`sfx_`/`bgm_`/`font_`/`atlas_`);代码与场景 PascalCase 且与类名一致。数据层 `crop_code` 保持 UPPER_SNAKE(设计稿 §5.2 口径),仅入文件名时转小写;内容 JSON 为例外,固定 `content/<域>.json`(§5.2 已写死该名)。场域 code 定为六个小写 snake,附属阶段沿用所属场域。
- **加载管理器选「纯类单例」而非 `Component`**:资源需在首场景加载**之前**可取,`Component` 会引入「引导节点必须最先加载」的隐性顺序约束。**引用计数契约:加载即 +1,必须成对 release**,实际回收交 `releaseUnused()`。
- **本机未安装 Cocos Creator 编辑器**:`assets/` 树、`package.json`、`tsconfig.json` 已手写就位,但 `.meta`、`settings/`、`library/` 只能由编辑器首次打开时生成;两个分包需人工在编辑器内「配置为 Bundle」且名字须与 `AssetPaths.BUNDLE` 逐字一致。TS 已用 `cc` 类型桩跑 `tsc --noEmit`(strict / noUnusedLocals / noImplicitReturns 全开)通过,**但未经编辑器实测**。

- **客户端 = Cocos Creator 3.8,一套代码两路构建**:web-mobile(浏览器 / ihomy 的 `/tools/garden` 内嵌)+ native(Steam / Windows / macOS / Linux / iOS / Android)。**Tauri 桌面壳方案作废**。
