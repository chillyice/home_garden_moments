# 踩坑速查

> 按「症状 → 真因 → 对策」记录;`AGENTS.md` 只留结论与指针。本仓刚立项,先记本机环境(Windows + PS 5.1)已实踩的通用坑。

## 1. PowerShell 5.1 与中文文件

- **症状**:脚本改写后中文变乱码;或文件头多出 BOM 导致解析报错。
- **真因**:PS 5.1 默认按 GBK 读写(`Get-Content`/`Set-Content`/`WriteAllText`);`WriteAllText` 还会带 BOM。
- **对策**:含中文的文件一律走 Read/Write/Edit 工具;脚本化改写用 Python `open(p,'rb')` 读 + 保行尾写(本仓 `core.autocrlf=true`,行尾 CRLF)。
- **症状**:内联在 `python -c "..."` 里的 Markdown 反引号整段丢失,`` `f `` 还变成了不可见换页符(文件里凭空出现控制字符)。
- **真因**:PowerShell 双引号串里反引号是转义符(`` `f `` = 换页符 FF,其余 `` `x `` 被吞),内容经 shell 一层必坏。
- **对策**:**脚本一律用 Write 工具落成 `.py` 文件再执行**,不内联进 shell;改完断言无 `\x0c`(`assert b'\x0c' not in b2`)。

## 2. 终端显示乱码 ≠ 文件损坏

- **症状**:Python `print` 中文报 `UnicodeEncodeError`;`Get-ChildItem`/`git status` 里中文路径显示 `??` 或乱码。
- **真因**:控制台代码页是 GBK/ASCII,输出层编码问题,文件本体是 UTF-8。
- **对策**:`$env:PYTHONIOENCODING='utf-8'` 再跑脚本;核实文件内容以 Read 工具或 `git status --short` 为准,别凭终端显示判断。
